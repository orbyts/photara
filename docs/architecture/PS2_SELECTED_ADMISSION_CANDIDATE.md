Non-null variants, births, publication, cleanup and retirement are unsupported here. The prospective operation-receipt body is a **template under the prepared original**, not evidence of acceptance: the actual admitted journal and operation index still contain exactly the original three operations. All earlier receipts retain their exact bytes.

## Independent complete layout regeneration

The Python generator imports the settled Builder's pure frame/tree helpers. It copies every original allocation byte, including padding, before appending; it never fills old padding in place. It prepares a new active StateRoot with fresh authored-origin association identities, rotates recovery to the exact old active StateRoot, and preserves the retained root. All seven tips, including shared root-placement metadata, receive finite append corridors. Every retained placement owns the complete extended shared metadata extent.

A separately implemented Rust decoder reconstructs the complete planned semantic objects, ownership claims/trees, locators, global base inventory and root-placement tree from authenticated old prefix bytes and actual Core output. It reads no prospective corpus, diagnostic future-record cache or future allocation file. The supported specimen layout is explicitly bounded: one next operation, existing seven-tip topology, existing source-association leaf shape, prescribed fresh specimen IDs, existing tree framing and a fixed per-tip corridor. These are test codec limits, not package lifetime or production policies.

The admission verifier compares every regenerated allocation byte and target reference with the supplied prospective candidate. The full shared typed reader independently verifies that prospective candidate's schema-directed closures, per-root ownership, observations, original source association identities, receipts and accounting. The new active receipt sequence must equal old accepted prefix plus the exact prepared receipt, and its authored coordinate must equal the actual Core result. Raw suffix hashes/counts cover unreachable frames as well as selected records. A negative inserts another valid unreachable frame and coherently updates its recipe hashes: the ordinary prospective selected closure still validates, but the original deterministic decoder refuses the changed bytes.

This prospective package has its own empty-hold sizing selector. **It is not a published successor of the admitted O/P hold.** No write, acceptance, finalizer selection or charge settlement is executed. Maximum-width finalizer/phase/ledger control shapes are sizing sentinels only; they are not selected measured observations. Their same-tip null birth fields and finite write descriptors constrain this pending codec, not the newborn variant's semantics.
