# Selected D19 Blob through the shared reader

Unfrozen, test-only, read-only candidate. This completes the standalone same-project composition described in [the plan](PS2_SELECTED_BLOB_COMPOSITION_PLAN.md); it does not select a permanent format or production storage profile.

The unchanged [D19 corpus](../fixtures/generation-two/d19-package-specimen.json) establishes trusted legacy identity and bytes. Its original project, library, bootstrap, authored/history closure, managed resource v1 and representation v2 remain unchanged. The existing [657,394-byte selected corpus](proposals/ps2/selected-blob/linked.json) now passes the same `wire.rs` HEAD, physical placement, ownership, inventory and accounting driver used by the Graph fixtures. Its historical preparation status string remains unchanged; this document and the new test target record the later verification.

The reader preserves the JSON `(sha256, length)` API and adds explicit mixed ObjectRef keys only where inventories and locators require them. A separately trusted `PackageContext` supplies original allocation registration, identity/features and the narrow unchanged legacy semantic closure. Common code checks StateRoot v2, the actual empty operation-index trees and zero prefix, null resource/conversion dispatch, typed memberships, exact allocation sets and finite control allowance. Default Graph, original-admission, origin and phase paths retain their entry points; raw allocations are refused by their transition codec.

Active and recovery select the same D19 StateRoot. Both independently open with zero current media bytes read and zero media hashes. The three original allocation registrations total **348,160 charged bytes**, including 65,536 standing control bytes and 16,384 directory allowance. The raw allocation is a five-byte whole Blob, charged 4,096 bytes. Original extent/inode observations come from fixed trusted registration, never from the selected ledger or current provider. Combined framed/raw loading is bounded to 16 allocations and 16 MiB in this fixture; this is not a product media-size limit.

Explicit strong audit consumes the Blob-to-allocation mapping returned by a fresh shared structural proof and reads/hashes the five media bytes. Same-extent corruption still structurally opens and fails audit; same-byte inode replacement refuses structural opening. Ordinary structural verification has no raw byte getter and does not compare current media with the golden bytes.

[Seven independently rebuilt negative vectors](proposals/ps2/selected-blob/shared-negatives.json) rehash actual frames, physical selectors and outer controls. They reach exact errors for unknown StateRoot fields/version, incorrect zero-operation prefix, wrong raw ownership layout, unsealed raw ownership, understated charge and a second selected role assigning a different Blob identity to the same original raw allocation. Exact same-Blob sharing remains valid. The latter vector isolates the cross-role physical identity check before its conflicting semantic selection is considered. Further focused checks cover missing capability, null-conversion misuse, changed original witness and raw transition refusal.

Validation and exact source/output hashes are in [the evidence manifest](verification/ps2-selected-blob-shared.json). The original preparation source/corpus hashes remain unchanged. Shared-source changes are limited to the test reader and the origin test's empty Resolver fields; no production code, migration, live package or capture policy changed.

Remaining boundary: this is standalone D19 with null ConversionSource and an empty operation history. It does not prove a converted D19 snapshot, Blob mutation/newborn admission, qualified writable media, or combined Graph/media operation. Converted Blob source handling still needs its distinct structural-versus-audit composition; current Graph source verification was not weakened. The context is a fixed preservation adapter, not an arbitrary legacy document decoder.
