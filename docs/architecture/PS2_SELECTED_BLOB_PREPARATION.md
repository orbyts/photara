# Selected Blob preparation and shared-reader handoff

**Preparatory, unfrozen, pure fixtures; no shared full-HEAD verification yet.** This implements only the new-file preparation authorized by the [composition plan](PS2_SELECTED_BLOB_COMPOSITION_PLAN.md). No shared reader, production code, original D19 bytes or permanent format changed.

The [generator](proposals/ps2/selected-blob/generate.py) imports the existing integrated Builder's frame packing, padding and object registration helpers in an isolated Python module. Its [linked corpus](proposals/ps2/selected-blob/linked.json) preserves the actual D19 project/library/bootstrap and selected legacy object bytes. New control records form a standalone candidate HEAD/commit/RootSet/StateRoot: same active/recovery root, null predecessor/ConversionSource/ResourceState, zero accepted operations, empty pins/evidence/holds/tickets, framed JSON placement and the one existing raw `photo` Blob. The source archive is reference input only. Mixed inventory/locator order includes unchanged ObjectRef kind.

The corpus declares two framed tips of 131,072 bytes and one five-byte sealed raw allocation. The generic integrated accounting subproof verifies modeled charge 348,160 = 262,144 tips + 4,096 raw charge + 65,536 standing controls + 16,384 conservative namespace/directory allowance. The latter covers the three allocation names and their containing directory under this synthetic profile; it is not an inode measurement or future refund. Retained-source charge is zero because no conversion snapshot is selected.

[The new Rust target](../../crates/photara-store/tests/selected_blob_candidate.rs) proves canonical generation, exact original typed closure preservation, instrumented structural/audit separation, changed/missing allocation and project refusals, and that generic accounting accepts this raw observation/ledger without media reads. It extracts supplied framed JSON for these adapter tests; extraction does **not** establish selected locator/global ownership closure. Diagnostic records do not supply missing current semantic bytes.

[TrustedLegacy](../../crates/photara-store/tests/selected_blob_candidate/legacy.rs) runs the actual unchanged v1.1 reader on all original D19 files during fixture setup. That strong setup hashes the original Blob, then retains only verified JSON bytes, typed ObjectRefs and identity; it stores no original raw media bytes. Its semantic adapter subsequently requires the exact original authored/history references and supplied current JSON bytes, and describes current Blob extent through an injected callback. It is a validated-snapshot preservation adapter, not a general legacy schema implementation.

[Media](../../crates/photara-store/tests/selected_blob_candidate/media.rs) keeps current raw bytes private. `describe` and `structural` expose only extent/identity; only `audit` reads/hashes content. Setup decoding is outside counters. Structural adapter and accounting runs record zero current-media reads/hashes; audit reads five bytes/hashes once. Same-inode/same-length content corruption passes structural metadata and fails audit; same-byte inode substitution refuses original registration. None of this establishes physical durability or provider qualification.

## Minimal shared API after admission ownership is handed off

The concrete new seams should be added to the shared reader, not implemented as another permissive HEAD decoder:

| Shared seam | Required contract and existing adapter input |
| --- | --- |
| Identity/feature context | Immutable `{project_id,library_id,bootstrap_sha256,original_manifest_bytes,expected_required_features,profile,incarnation}` supplied from validated fixture setup. Every selected body/envelope must match it; exact feature union retains original features. Defaults preserve the current Graph context. Do not accept each object's own identity as its trust anchor. |
| Semantic snapshot hook | Given actual parsed StateRoot and authenticated resolver, `TrustedLegacy::verify_semantic_metadata(authored,history,json_resolver,blob_extent)` returns the unchanged legacy typed member set. Shared code independently checks the new StateRoot identity, v2 index zero-prefix seed, canonical empty ID/ordinal trees, inventory equality and null journal inclusion. Current Graph receipt/no-op/retry checks stay on their existing path. |
| Kind-aware selected keys | Use actual ObjectRef (or exact `(kind,sha256,length)`) for mixed inventory/locator sets and ranges. Keep JSON-only helper conversions explicit. JSON `get` cannot return a Blob or infer membership from content. |
| Raw allocation provider | Shared allocation dispatch distinguishes framed bytes from a `Media` provider/handle. `describe(allocation_id)` supplies current extent/local witness without revealing raw bytes. Whole-Blob locator/claim/hash commitments and the external original registration must agree. The explicit audit entry receives the structurally selected mapping and calls `audit`; structural paths cannot access raw bytes directly. |
| Accounting registration | Pass project-scoped immutable original evidence to the existing generic ledger validator. It already supports `whole-blob`; do not derive original charge/witness authority from the current ledger. Current framed tips and raw sealed allocation must cover the exact supplied physical set once. |
| Empty/null dispatch | Empty retained-root/evidence/operation trees are explicit valid shapes. Null ResourceState requires absence of managed-backing feature; null ConversionSource requires empty retained-file charges and no retained source files. Shared closure/control checks still run; these variants are not flags that skip validation. |

Shared physical tree/frame/locator/ownership/control verification must prove the complete new corpus, including both root roles and raw layout. Only then may the candidate claim a full HEAD result. That subsequent slice also needs coherent missing Blob inventory/locator/ownership, wrong layout/kind, equal-total charge swap, omitted namespace, unsupported feature/schema, and mixed-kind key negatives through the actual shared entry.

Evidence is recorded in [the preparation manifest](verification/ps2-selected-blob-preparation.json). Tests include four new preparation cases plus six unchanged inherited accounting cases. Full selected HEAD validation, Blob-containing ConversionSource structural/strong audit separation, Graph mutation with Blob resources, factored resource/v3 integration and actual storage transitions remain open. The linked corpus deliberately declares `unfrozen-preparatory-not-shared-head-verified`.
