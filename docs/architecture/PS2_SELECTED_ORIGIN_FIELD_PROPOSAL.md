# Selected retention-origin field proposal

**Unfrozen engineering field proposal; not implemented, approved permanent format, or a release/expiry policy.** This is the next bounded origin-dispatch slice after the [integrated settled candidate](PS2_INTEGRATED_SETTLED_COORDINATE_CANDIDATE.md), whose ResourceState v2 reader supports authored origins and an empty evidence leaf only. It instantiates the [origin evidence proposal](PS2_RETENTION_ORIGIN_EVIDENCE_PROPOSAL.md) while preserving the [approved capture/retention distinction](RESOURCE_STORAGE_AND_VERIFICATION_CONTRACT.md#capture-is-not-indefinite-retention). No frozen source or schema meaning changes.

## Exact proposed records

Keep ResourceState v2, retention-requirement v1 and retention-source v1 unchanged. A source remains `{association_id,origin:{kind,source_id},requirements:Ref}` beyond its common envelope. An association ID denotes one immutable exact record; changing origin or subset creates a new ID. Multiple associations may share an origin or overlap requirements. RootSet v2 already selects `retention_evidence:Ref`; no additional selector is introduced.

`Ref` is the unchanged JSON ObjectRef; `Id` is canonical nonnil UUID; `D` is canonical u64 decimal text; `H` is lowercase SHA-256. Every record below has exact common fields `schema:{id,version:1}`, `project_id`, `extensions`. Evidence bodies additionally carry `library_id,bootstrap_sha256`, checked against the selected package. Extensions use QualifiedName keys, bounded preserved values and no inferred edges. Unknown fields/versions refuse. Proposed required capability **`photara.resource-retention-evidence.v1`** is additive and unfrozen; a non-authored origin requires this dispatch before interpretation. It does not replace `photara.resource-backings.v1` or `photara.resource-state-trees.v1`.

| Proposed schema ID, v1 | Fields beyond common envelope |
| --- | --- |
| `photara.resource.retention-evidence-leaf` | `count:D, entries:[{key:OriginKey,evidence:Ref}]` |
| `photara.resource.retention-evidence-branch` | `count:D, children:[{first:OriginKey,last:OriginKey,count:D,child:Ref}]` |
| `photara.resource.history-retention-context` | Package identity above; `source_id:Id, state_root:Ref, history:Ref, promise:"reconstruct-selected-versions", requirements:Ref` |
| `photara.resource.recovery-retention-context` | Package identity; `source_id:Id, state_root:Ref, role:RecoveryRole, requirements:Ref` |
| `photara.resource.retention-policy` | Package identity; `policy_id:Id, revision:D, requirements:Ref` |
| `photara.resource.pending-retention-intent` | Package identity; `operation_id:Id, request_sha256:H, requirements:Ref` |
| `photara.resource.pending-retention-evidence` | Package identity; `operation_id:Id, request_sha256:H, token:D, original_admission:Ref, retention_intent:Ref` |

`OriginKey={kind:"history"|"recovery"|"explicit"|"pending",source_id:Id}`. Keys compare kind UTF-8 bytes then UUID canonical bytes; child ranges are strict, ordered, disjoint and exact, with checked counts. Empty means exactly one empty leaf. Authored has no evidence-tree entry: its authority is the actual owning selected root. Leaf evidence schema and identity must match its key. Branch/leaf and all listed Ref fields are typed edges; `requirements` uses the existing typed resource selection tree with selection_kind `requirements`. IDs/digests, enum strings and extensions are nonedges.

`RecoveryRole={kind:"current-recovery"}` or `{kind:"retained-recovery",pin_id:Id}` with exact variant fields. The second variant resolves the selected retained-root entry with the same pin ID, reason `unresolved-recovery`, and exact state_root Ref. It is not a new pin reason. Evidence-tree records are included in the exact global union and authenticated placement/ownership. They are not silently inserted into each StateRoot semantic inventory.

The original-admission variant that supports pending resource work adds the exact typed field `retention_intent:null|Ref` selecting the proposed intent above. Its immutable codec must explicitly support this field; this is not an extension-based reinterpretation of frozen admissions. Null means no pending resource requirement authority. Final admission/phase schema IDs remain the [original/finalizer integration dependency](PS2_NEWBORN_ORIGINAL_FIELD_PROPOSAL.md#whole-head-seam-and-remaining-evidence); no historical reader acquires this field by default.

## Resolution from the selected package

Build a resolver from actual HEAD/commit/RootSet, all active/recovery/pinned StateRoot bytes and per-root placements, the selected evidence tree, and selected holds. Reject one root UUID with contradictory bytes. Predecessors, receipt provenance and caller-provided ID lists add no roots or authority.

| Association origin | Exact validation |
| --- | --- |
| Authored | source_id equals the **owning** selected StateRoot root_id. Its ResourceState selects the association and exact requirement subset alongside its authored projection. Any retained role may retain that authored snapshot. No evidence-tree entry is needed or allowed for this kind. |
| History | source_id equals owning StateRoot root_id. The keyed history-context selects that exact StateRoot Ref and exactly its `history` Ref. Its promise explicitly declares reconstruction of the versions named by its requirement tree. The association subset must be identical selected requirements of that context. |
| Recovery | source_id equals owning StateRoot root_id. The keyed recovery-context selects that exact StateRoot and resolves its current recovery role or exact unresolved-recovery pin. Its requirement subset matches the association. Being an arbitrary active/history/undo pin does not establish recovery-role evidence. |
| Explicit | source_id equals selected policy_id. Exact policy revision/body is selected under that key; association requirements must be identical members of its requirement tree. The policy record itself supplies the explicit portable declaration allowed by the existing appendix; no receipt, credential or hypothetical command is invented. |
| Pending | source_id equals original OperationId. Evidence operation/request/token/intent exactly agree with the selected original admission. Its intent fixes the same requirement subset before effects. The **currently selected phase under that original hold** must be a codec-defined unresolved phase, including retained unknown outcomes; a receipt or detached original alone is insufficient. |

For each history/recovery/explicit key, its requirements equal the union of association subsets using that key across the selected roots. The same is required of pending intent requirements. Overlap is allowed but equal requirement IDs must denote equal canonical records. Reject unresolved association keys, contradictory shared association identity, missing members, and evidence keys with no selected association. This is an exact selected-state consistency rule, not authority to remove a policy or requirement during publication. A policy retaining requirements must continue to have a selected association; dropping both is a separate release transition needing its existing authority. No evidence alone grants local mutation or qualified media access.

History is a precise **new typed declaration**, not a reinterpretation of legacy `history` artifact `retention` strings. The declaration binds an exact history projection plus exact resource/version requirements; it neither promises that every historical artifact is reconstructable nor invents item-level promises from free text. No legacy history rewrite is needed. If a later product needs narrower historical entry IDs, a distinct reviewed typed context is needed; this slice does not guess those semantics.

Recovery rotation may preserve the exact old root, source associations and requirement bytes by selecting an unresolved-recovery pin and a replacement context whose role names that pin. Evidence bytes change; association identity need not change because its original root identity and subset did not. Rotation without the required retained context refuses while those recovery associations remain. This does not authorize creating/releasing a pin automatically or silently relabeling it as authored.

## Acyclic construction and verification order

Construct immutable requirements/subset trees, then associations with source IDs, ResourceStates and semantic StateRoots. History/recovery context records may now point to actual completed StateRoots; RootSet selects those contexts outside the StateRoot closure. Explicit policies can be constructed before roots because they refer only to requirements. There is no source association back edge to the evidence record.

For pending work: fixed requirements → pending-retention-intent → original admission → pending-retention-evidence → evidence tree → selected phase/accounting/RootSet. The original semantic target can contain an association naming OperationId, but must exclude the admission-dependent evidence tree and future global inventory. Pending evidence points to the original and immutable intent, **not** to the current phase/envelope/RootSet. The reader verifies phase liveness through the selected holds tree. A finalizer's target evidence Ref remains a prospective commitment; selected RootSet supplies the actual edge. Never make admission or finalizer depend on the hash of its containing controls.

A bounded metadata open validates original/phase identity and the origin's selected unresolved status without executing an operation. Pending positive vectors require an actually parsed selected admission/phase/hold path; a test parameter `pending=true` is not evidence. Until the new admission codec/phase table exists, implement the other four origins and leave pending explicitly unsupported. This is an engineering dependency, not a request to choose a new pending-release policy.

## Minimum executable follow-up and boundary

Add new-only generator/reader tests under the proposed coordinates, leaving the settled fixture unchanged. First construct authored/history/recovery/explicit cases from actual selected roots and typed context bytes, including one requirement shared by distinct sources and roots. Then add pending when exact selected original/phase dispatch exists. Use existing tree/parser bounds as explicit disposable bounds; no lifetime source-count ceiling follows from the five tags.

Positive vectors: exact history promise with unchanged legacy history bytes; explicit policy with arbitrary overlapping source subsets; recovery rotation preserving the old root under its exact pin; shared requirement retained after one association disappears in a separately authorized transition; and pending original intent through an unresolved/unknown phase. Releasing one source must not remove another source's requirement, backing or physical pin. The twelve operational blockers remain separately checked; ReaderLease handles are not portable evidence.

Coherently rehash negatives for: same history source ID but wrong StateRoot/history Ref; legacy retention text without the typed declaration; wrong recovery role/pin reason/root; policy ID/revision/subset substitution; wrong operation/request/token/intent; a terminal or missing hold presented as pending; original-to-evidence back edge; duplicate keys/overlapping branch ranges/count errors; contradictory shared association or requirement identity; unknown field/version/capability; and missing global membership/physical ownership for evidence. Structural reading of an unsatisfied copy/qualification requirement remains possible; retained-publication admission is a separate result, and external media reads remain zero.

The existing contracts already authorize these five origins, explicit reconstruction declarations, and conservative pending retention. No new expiry, minimum replica default, release workflow, security grant, provider qualification or production policy is chosen here. Actual commands that establish or end a policy/history promise, production custody/authorization, and permanent approval of these exact names/bytes remain outside this disposable validation slice. Failure to resolve a required origin fences that selection; it is not permission for automatic deletion or origin rebinding.
