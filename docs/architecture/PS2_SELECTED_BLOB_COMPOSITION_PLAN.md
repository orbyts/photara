# Selected Blob composition plan

**Unfrozen, documentation-only implementation plan.** The next bounded proof is one standalone HEAD-selected package in the **original D19 project**, using the new physical/accounting coordinates and exact existing authored bytes. It is not Graph mutation, a conversion transaction, capture, publication, or permanent format approval. The existing [six whole-Blob tests](PS2_WHOLE_BLOB_BYTE_CANDIDATE.md) remain component evidence; they need not be repeated as new results.

## One concrete positive package

Use [the original D19 package](../fixtures/generation-two/d19-package-specimen.json): project `62000000-0000-4000-8000-000000020000`, owning library `62000000-0000-4000-8000-000000020001`, authored revision `1`, original format 1.1 bootstrap bytes and its actual selected authored/history references. Its 38-file original package contains the one five-byte managed Blob `photo`. Preserve the exact managed-resource v1, representation-content v2 and other selected legacy JSON bytes in this project. Never rewrite their project/library IDs to fit the separate Graph fixture.

Create new proposed-coordinate control metadata: one StateRoot v2 with those exact authored/history references, a new root UUID, truthful null predecessor, `resource_state:null`, an empty operation-index v2 with the existing zero-accepted-prefix codec, null journal inclusion, and a typed semantic inventory. Active and recovery may select this same independently valid root; pinned-roots, retention-evidence, holds and retirement-tickets use canonical empty trees. RootSet v2 selects its placement, global inventory overlay and accounting envelope. The new outer commit is explicitly a **standalone settled specimen**, with revision 1/null parent; it does not assert succession from the old commit. HEAD selects only that new commit. Outer authored/history/inventory equal active StateRoot fields.

Set `conversion_source:null` consistently in RootSet and ledger. Original D19 files are immutable **reference input**, not selected retained snapshot files or uncharged copies in this package. This first proof preserves selected semantic bytes and original bootstrap identity; it makes no original-file conversion-retention claim. Keep all original bootstrap capabilities and require the new sealed/scalable/accounting/whole-Blob capabilities and proposed reader floor. Do not require resource-backings/resource-state-trees merely to reuse their fixture: legacy managed v1 and representation v2 do not become CapturedVersion/backing/retention-source records. No new capture or retention policy is needed.

The first selected Blob is exactly the Blob reached by the unchanged legacy managed-resource record. Do not add the component's otherwise unreferenced empty Blob to a global inventory that claims exact semantic closure. Empty-allocation handling remains independently proven until a genuine selected semantic case is constructed; five-byte extent substitution with an empty allocation is a negative here.

The trusted reference validation **does hash its original Blob**. That is a one-time fixture setup/strong compatibility check and must be separately instrumented or staged outside candidate structural opening. Every structural-open test thereafter receives the fixed validated reference authority and the current supplied allocations. It must not rerun the original reader, compare current raw bytes to the golden, or smuggle a media hash through accounting/inventory construction. The exact original inventory/JSON bodies, previously authenticated, establish existing semantics without rewriting them.

Use the shared physical tree, frame, ownership, control and accounting reader for both Graph and D19 contexts. Avoid a second independent permissive Blob-only RootSet decoder. The new fixture may have fewer roles and zero accepted operations, but canonical empty selectors require explicit support rather than bypassing checks.

## Structural open and explicit audit

`open_structural` verifies sole HEAD/commit dispatch, exact semantic metadata/inventories, whole-Blob reference/extent/layout, original local witness, ownership, charge, namespace allowances and complete actual physical/control sets. It does not read/hash raw media to establish digest freshness. Synthetic witness matching remains unqualified local evidence.

`audit_selected_blobs` uses the structurally selected Blob-to-allocation mapping and explicitly streams/reads the whole raw allocation to verify exact length and SHA-256. A same-identity, same-length content change must pass structural opening and fail this audit. A same-byte replacement with another registered witness must fail the local identity check. JSON metadata is still hashed/canonical-parsed during ordinary opening; no media-hash prohibition removes metadata integrity checks.

Required new whole-HEAD vectors: exact D19 semantic bytes and original ObjectRefs; old reader UnsupportedFeature before packed lookup; missing/wrong-kind Blob locator; framed/raw confusion or forbidden offset; missing/borrowed ownership; equal-total charge/observation swap; omitted namespace allowance; undercharge; raw corruption versus explicit audit; replaced witness; extra allocation/loose control; wrong project/bootstrap/library; a missing Blob semantic inventory edge; and unsupported schema/feature. Coherently rebuild downstream hashes for semantic negatives. Retain default Graph reader tests unchanged.

## Converted D19 remains a separate required composition

The current [integrated accounting reader](../../crates/photara-store/tests/integrated_wire_candidate/accounting.rs) hashes every retained file when checking supplied original file evidence. A D19 ConversionSource would include the original raw Blob, so blindly reusing that path would make ordinary opening hash media again. Graph-only source-file evidence does not close this gap.

A later converted-D19 fixture must select the exact original ConversionSource descriptor and all original file paths/length/hash commitments, retain and charge the original snapshot separately, and distinguish **structural read-only checks** from **explicit strong source audit**. Structural checks validate registered namespace, portable path, regular-file/type, extent and exact original local witness/charge; they do not claim current content verification. Strong audit hashes actual original snapshot bytes against the immutable descriptor, including the Blob. Preserve descriptor commitments and original bytes; do not silently omit/rewrite the Blob path or equate current and snapshot allocations without identity proof. Writable admission, qualified capture and conversion publication still require their existing strong proofs and barriers; a metadata-open result does not supply them. This separation follows the approved no-ordinary-media-hash semantics and introduces no release or capture policy.

The first deliverable proves one genuine legacy Blob closure through the same proposed-coordinate HEAD/placement/accounting reader as the Graph specimen, with parameterized identity and explicit audit behavior. It does **not** prove newly captured media in a Graph operation, factored resource/v3 binding composition, Blob rollover/retirement, converted-source Blob support, streaming multi-gigabyte performance, qualified storage, or a universal production legacy decoder. Those claims stay open until their actual selected bytes and transitions are tested.
