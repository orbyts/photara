# Selected transition implementation plan

**Engineering proposal; unfrozen, not implemented, not format approval.** This plan starts from the actual new-coordinate [integrated generator](proposals/ps2/integrated/generate.py), [whole-package reader](../../crates/photara-store/tests/integrated_wire_candidate/wire.rs), and [accounting reader](../../crates/photara-store/tests/integrated_wire_candidate/accounting.rs). It does not migrate or reinterpret the historical [single-HEAD route](../../crates/photara-store/tests/single_head_route_candidate/contract.rs). The latter supplies tested ordering and recovery ideas, not bytes or authority for this epoch. The [newborn field proposal](PS2_NEWBORN_ORIGINAL_FIELD_PROPOSAL.md) and [RootSet integration plan](PS2_FINAL_COORDINATE_INTEGRATION_PLAN.md) remain the composition boundary.

## First increment and preserved identities

Implement a selected **admission-only successor** first: the new settled HEAD → one pending original hold, with exactly unchanged semantic roots, per-root physical placements, ledger, receipts, conversion metadata and original files. Every effect in this increment is a bounded loose control selection; there are no packed writes or simulated births. The admitted payload is the next genuine Core/PS1 Graph operation after the selected active accepted prefix, not a fabricated receipt. Its target and deterministic recipe are prepared and bounded now; executing them is the following increment.

Preserve the specimen's actual profile/incarnation, eight existing allocation identities, exact sealed charge reference, seven tip observations, retained-file charges, original receipt bytes and all retained roots. Do not import the historical route's incarnation, four-tip topology, charges, or original token. Original project capacity is chosen before admission using the same explicit fixture rule as the later replay; never increase it to make a failing phase fit. Physical observations remain synthetic externally supplied evidence. Neither a matching witness nor a serialized barrier value grants writable qualification.

The following code increment executes **same-tip Graph publication and cleanup**, with birth fields null and no rollover. A recipe exceeding an existing extent/corridor or control allowance refuses before admission. This establishes the new epoch's selected O/P/C seam before adding witnessed births. It is useful positive evidence even when the original same-tip bound produces a negative workload result; it does not complete newborn support.

## Exact proposed selected controls

Use the existing checked scalar grammar: nonnil canonical UUID `Id`, decimal u64 text `D`, lowercase SHA-256 `H`, qualified name `N`, unchanged JSON `JRef`, and existing direct `PhysicalRef`. Every new control has exactly the common `schema`, `project_id`, `extensions` envelope. Qualified extension values are opaque nonedges, preserved in canonical identity and included in bounds. New proposed IDs below are version 1; unsupported versions/codecs refuse. None is an alias for `example.ps2.*` bytes.

`SemanticTarget={active:JRef,recovery:JRef,pinned_roots:JRef,operation_index:JRef,conversion_source:null|JRef}` binds prepared exact semantic objects; recovery is the exact prior active root and pinned-root bytes are unchanged. It excludes global inventory, placement, accounting and admission-dependent retention evidence. For the first same-tip codec, `PayloadRecipe={codec:N,allocations:[{allocation_id:Id,arena:"data"|"metadata",witness:{device:D,inode:D},original_end:D,original_sha256:H,final_end:D,frame_count:D,framed_sha256:H,recipe_sha256:H}]}`. Entries are sorted unique allocation IDs. The immutable supported decoder regenerates exact raw framed append bytes from the original authenticated base, intent and target objects; `recipe_sha256` commits its canonical per-allocation write plan. Every raw suffix includes unreachable intermediate frames. Existing bytes, witnesses and absence of unexplained tails are independently checked. A proposed specimen decoder name such as `photara.codec.ps2-same-tip-graph-v1` must be backed by that implementation before acceptance; the name alone supplies no replay proof.

`Bounds` is the exact existing newborn proposal's control-bound shape. For a same-tip admission, marker and newborn-binding byte bounds are zero, the corresponding controls are forbidden, and all applicable finalization/phase/aggregate limits are positive. This explicit codec dispatch resolves the proposal's otherwise positive birth-bound rule without silently permitting birth. Before coding, register this variant rule alongside the decoder. No numeric limit is increased by this plan.

`old` retains exact canonical reconstruction bodies as **provenance commitments**, not recursive traversal edges into every historical root. Its `states` contains exactly the distinct selected active/recovery/pinned StateRoot bodies sorted by ObjectRef; each body must reproduce its key and original root-placement selection. The caller authenticates these against the actual initial package before admission. Future fresh-handle verification checks the unchanged exact old HEAD/commit chain and these admitted bytes; it must not accept a caller-supplied alternative old ledger. Canonical source bytes must be retained directly, not recovered by permissive reserialization. A first bounded fixture may carry the needed original immutable objects in its diagnostic corpus; the replay entry must explicitly declare which are required and refuse their absence. It must not silently consult an entire historical snapshot.

O's intent/receipt, old_hold and generation-plan references are declared typed edges. `old_hold` must be the exact canonical empty hold root selected by the original envelope. Keeping this finite original admission dependency makes the unchanged packed base's old empty-hold implementation record legitimate; merely replacing the selector and leaving that base member unreferenced would violate exact global closure. It is not permission to retain arbitrary stale accounting nodes or an old nonempty hold tree. O's target references and embedded old records are commitments/reconstruction inputs, not current retention edges. P's original, newborn-binding and finalization references are edges. Hold references to O/P are edges. These logical dependencies and all hold implementation nodes belong to the exact global union; controls stay outside the packed base when not already members. The accounting envelope remains exactly `{ledger,holds}`. It must not gain a competing original/phase selector.

## Acyclic phase and charge selection

The first reader accepts `Stage="admitted"` only: `C=0`, remaining `R`, null binding/finalization/cleanup. It independently proves `old.total_charge + R <= project_limit` with checked arithmetic, and worst permitted payload/finalizer positive growth plus cleanup fits R. Full selected control coexistence must fit the original standing pool before creating any candidate. The selected hold does not increase settled physical `total_charge`; it contributes separately to committed capacity.

Subsequent explicit stages are `birth`, `payload-complete`, `finalizer-selected`, `published`, `clean`. Same-tip dispatch skips birth; birth dispatch requires the exact generation-plan and monotone selected binding before any payload acceptance. Until publication C remains zero even when actual sealed measurements have become available: unselected payload/finalizer allocations remain covered by original R. At finalizer-selected, semantic roots and authoritative charged ledger are still the original ones, while the selected finalization control embeds authenticated measured sealed bodies and its exact prospective recipe.

Publication simultaneously selects new independent root placements, semantic/global closures, actual ledger and P with `C` equal to the sum of positive registered high-water deltas plus newly registered charges. Transferring an already charged old tip into a sealed leaf adds no charge again. Preserve all unrelated sealed, retained-file and namespace/control charges exactly. Remaining is `R−C`, and before cleanup it is at least the original cleanup bound. Final-tip observations are measured only after finalizer barriers and remain embedded in the loose ledger; they cannot be packed in their own future-measured allocation. Validate exact observed identities, not only aggregate equality.

Clean keeps original R and C immutable, selects remaining zero, and records the exact bounded cleanup result; there is no second growth settlement. The hold summaries therefore derive reserved from O, consumed from P, and remaining from P: **do not enforce reserved=consumed+remaining after clean**. For this finite proof keep the zero-remaining terminal entry selected to test exact retry. Removing that evidence and composing a second operation require a separately specified bounded terminal-proof/cleanup corridor; this slice does not propose an indefinitely accumulating receipt list or an unselected retry authority. Graph operation receipt retention remains its existing full index.

O never refers to P, its current hold tree, envelope or global overlay. Finalization Target follows the newborn proposal's per-root-placement projection, including later retention evidence but excluding current accounting/overlay/F identity. Generated finalizer bytes may contain sealed records and implementation pages, but must not include F or P in a cycle. The envelope and overlay are built last as bounded loose controls. Direct physical root-placement trees cover all distinct retained roots, not just active/recovery.

## Native-free implementation and validation order

Add a new integrated transition generator/corpus and Rust child reader. Reuse the new integrated scalar, typed closure, physical-placement and accounting metadata validators; do not route final-coordinate objects through historical example-schema decoders. Keep settled entry points and fixtures intact. Extend accounting through a separate selected-hold proof returning original R, C, remaining and logical/implementation sets; the current settled `verify`/`metadata` must continue refusing nonempty holds unless the caller explicitly dispatches the transition reader.

1. Authenticate the actual initial HEAD/bootstrap/commit and full settled package, including every pin placement and independent original observation. Prepare a real operation/receipt and exact target semantic closures; preserve all earlier receipts and source identities.
2. Compute exact deterministic writes, worst-width future controls and finalizer shape. Count rounded simultaneous old/candidate immutable controls, both mutable selectors, journal/intent/staged roles and directory allowance. Check bounds/overflow/capacity without future retirement credit. Native-free tests model these roles explicitly; they cannot claim a real fsync result.
3. Build O and admitted P, then bounded loose hold/envelope/overlay and the exact successor HEAD. Verify exact old-plus-one commit succession, no unexpected controls, full per-role closure and no packed changes before accepting that admission vector.
4. On replay, select original codec by the stored original identifier and authenticate its immutable bytes. Reconstruct planned bytes, validate original prefixes/witnesses and allowed partial suffixes before simulated write steps or control cleanup. Unsupported codecs, occupied unborn paths, replaced identities and out-of-plan tails refuse with all original evidence preserved.
5. Add measured finalizer selection only after payload-complete observations. Validate embedded charge/observation references, exact sealed set, finite admitted corridor and all controls before accepting any finalizer effect. Rebuild the exact finalizer bytes; after their barriers, validate full destination suffixes and actual final-tip observations before joint publication.
6. Validate current complete controls and physical/typed closure before cleanup or terminal retry. No missing active-only files may be excused by the read-only recovery API when attempting publication or settlement. Recovery-only metadata inspection remains explicitly non-authoritative for mutation.

Tests first cover coherent changed R/old ledger/nonce/scope/receipt, same-total sealed or observation swaps, wrong tip class, duplicate/missing hold entries, forged summaries, unsupported original codec, changed original canonical bytes, maximal control widths and arithmetic overflow. Then add per-stage fresh-handle replay, unreachable suffix corruption, same-byte inode substitution, finalizer charge substitution, excess finalizer extent, partial-prefix/tail refusal, all retained roots and no double C at terminal retry. Post-unlink source-independent proof and once-only retirement credit require a later selected retirement variant with sparse original charge proof and actual fresh-absence evidence; **no retirement or credit field is accepted by this Graph-only increment**.

## Truly remaining newborn choices and next code task

The existing newborn proposal already fixes marker bytes, no-replace promotion, immutable witness binding, payload-before-F measurement, corridor confinement and late final-tip measurement. Those are not open policy questions. Remaining implementation choices are: the precise supported payload/finalizer decoder and deterministic changed-key sizing algorithm for seven existing tips plus retained-root placements; exact finite birth slots/corridor emitted by that decoder; codec-specific null/zero field dispatch; the complete simultaneous-control role schedule; the source of synthetic per-phase measurements and barriers; and the exact original-byte carrier/reader-version test. A distinct later codec must have a distinct concrete tested form. Supporting reader generation 2 with unchanged codec-v1 bytes alone proves replay preservation, not a v1→v2 format transition.

**Next bounded code task:** add the new canonical O/P/nonempty-hold records and a single admission-only successor of the integrated specimen, with an independently prepared genuine next operation, complete preflight, exact unchanged old physical/semantic closure, and coherent negative vectors. No payload effects, newborn creation, retirement, production changes or schema freeze. Once this passes independent review, execute that already admitted same-tip recipe through measured finalization/publication/clean; then replace the explicit no-birth dispatch with the existing proposed witnessed generation controls.
